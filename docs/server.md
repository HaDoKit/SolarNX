# Сервер для игры через интернет (экспериментально)

SolarNX Rendezvous — небольшой сервер, который вы запускаете на своём VPS (или любой машине с белым
IP-адресом). С ним режим «Интернет» работает **без проброса портов**: сервер «знакомит» ПК и Switch, а
дальше они общаются напрямую.

Как это работает:

1. ПК в режиме «Интернет» регистрируется на сервере под своим **ID** (8 символов, виден в настройках ПК).
2. Switch спрашивает у сервера адрес ПК по этому ID. Сервер сообщает Switch внешний адрес ПК, а ПК —
   адрес Switch.
3. Обе стороны одновременно отправляют пакеты навстречу друг другу, и роутеры пропускают этот трафик
   (так называемое пробивание NAT). Дальше видео, звук и управление идут напрямую, мимо сервера.
4. Если напрямую соединиться не удалось (например, у одной из сторон «серый» адрес провайдера), сервер
   может пересылать трафик сам — если вы это разрешили.
5. Если ПК и Switch подключены к одному роутеру, сервер даёт Switch локальный адрес ПК, и трафик идёт
   внутри домашней сети, не выходя в интернет.

Весь трафик между ПК и Switch **зашифрован** ещё до сервера — сервер видит только адреса и ID, но не
игру, управление или ключи. Подключиться к ПК может только Switch, привязанный к нему.

## Что нужно

- VPS или другая машина с белым IPv4-адресом: Linux (x64) или Windows (x64).
- Открытый в брандмауэре **UDP-порт 19020** (можно сменить).
- Для пересылки трафика — канал, рассчитанный на видеопоток: около 4–20 Мбит/с на одного игрока.

## Установка

### Готовая программа

Скачайте из [релизов](https://github.com/HaDoKit/SolarNX/releases) архив
`SolarNX-Rendezvous-linux-x64.zip` или `SolarNX-Rendezvous-win-x64.zip` и распакуйте. Программа
самодостаточная: ставить .NET отдельно не нужно.

```
./solarnx-rendezvous --key my-secret-key
```

Чтобы сервер запускался вместе с системой на Linux, используйте файл службы из архива:

```
sudo mkdir -p /opt/solarnx-rendezvous && sudo cp * /opt/solarnx-rendezvous/
sudo chmod +x /opt/solarnx-rendezvous/solarnx-rendezvous
sudo cp solarnx-rendezvous.service /etc/systemd/system/
sudo systemctl enable --now solarnx-rendezvous
journalctl -u solarnx-rendezvous -f      # журнал
```

### Docker

Скопируйте на сервер папку `Server` из репозитория (достаточно только её) и соберите образ в ней:

```
cd Server
sudo docker build -t solarnx-rendezvous .
sudo docker run -d --name solarnx-rendezvous --restart unless-stopped -p 19020:19020/udp \
  -e SOLARNX_RV_ACCESS_KEY=my-secret-key solarnx-rendezvous
sudo docker logs -f solarnx-rendezvous      # журнал
```

Пересылка трафика включается переменной `-e SOLARNX_RV_RELAY=true`.

## Настройки

Задаются в файле `rendezvous.json` рядом с программой (образец — `rendezvous.example.json`),
переменными окружения или параметрами запуска. Параметры запуска важнее переменных, переменные —
важнее файла.

| Файл | Переменная | Параметр | По умолчанию | Что делает |
|---|---|---|---|---|
| `Port` | `SOLARNX_RV_PORT` | `--port` | 19020 | UDP-порт сервера |
| `AccessKey` | `SOLARNX_RV_ACCESS_KEY` | `--key` | нет | ключ, который должны указать ПК и Switch. Без ключа сервером может пользоваться кто угодно |
| `Relay` | `SOLARNX_RV_RELAY` | `--relay` / `--no-relay` | выкл. | пересылать трафик, если напрямую соединиться не удалось |
| `RelayMaxKbps` | `SOLARNX_RV_RELAY_MAX_KBPS` | `--relay-max-kbps` | 20000 | предел пересылки на один Switch, кбит/с |
| `MaxHosts` | `SOLARNX_RV_MAX_HOSTS` | `--max-hosts` | 64 | сколько ПК могут быть зарегистрированы одновременно |
| `HostTimeoutSeconds` | `SOLARNX_RV_HOST_TIMEOUT` | `--host-timeout` | 60 | через сколько секунд тишины забыть ПК |
| `Verbose` | `SOLARNX_RV_VERBOSE` | `--verbose` | выкл. | писать в журнал каждый запрос |

`--config <файл>` — взять настройки из другого файла, `--help` — список параметров.

> Ключ доступа стоит задать всегда: без него ваш сервер смогут использовать другие люди. С включённой
> пересылкой это ещё и ваш трафик.

## Подключение ПК и Switch

1. **ПК:** «Настройки» → «Подключение» → режим **«Интернет (экспериментально)»**. В поле **«Сервер-посредник»**
   укажите адрес сервера (`example.com` или `example.com:19020`), в поле **«Ключ сервера»** — ключ.
   Запомните **«ID этого ПК»**. Включите трансляцию — ПК зарегистрируется на сервере.
2. **Switch:** главное меню → **X** → «Настройки»: **Режим** — Интернет, **Сервер** — адрес сервера,
   **Ключ сервера** — ключ, **ID ПК** — ID с ПК. Перезапустите SolarNX на Switch.
3. **Привязка** (один раз): на ПК «Привязать Switch…», на Switch «Привязать к этому ПК», сверьте 6-значный
   код. После привязки ID ПК запоминается сам.

Проброс порта на роутере ПК в этом режиме не нужен. Поле «Адрес ПК» на Switch при указанном сервере
не используется.

## Если не подключается

Строка «X  Интернет: …» в меню Switch подскажет причину:

| Сообщение | Что делать |
|---|---|
| адрес сервера не найден | проверьте адрес сервера |
| сервер не отвечает | сервер не запущен или UDP-порт закрыт в брандмауэре VPS |
| сервер не принял ключ | ключ на Switch не совпадает с ключом сервера |
| ПК нет на сервере | на ПК не включена трансляция в режиме «Интернет», указан другой сервер или ключ, или неверный ID ПК |
| ожидание ПК | сервер нашёл ПК, но соединиться не удалось: включите на сервере пересылку (`--relay`) |

В журнале сервера видно, какие ПК зарегистрированы и когда включается пересылка.
